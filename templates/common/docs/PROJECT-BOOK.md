# {{NAME}} — project book

For a human who wants to understand, and if needed rebuild, {{NAME}} without an AI.
SPEC.md says WHAT and WHY in rows; this book says HOW, in reading order. Update it when a wave merges.

1. **Purpose and users** — who uses it, on what device, the worst device that must work.
2. **Architecture** — the parts, how data moves between them (a text diagram is fine).
3. **Data model and algorithms** — every stored field; algorithms as numbered steps.
4. **Module guide** — one paragraph per module: what it does, which SPEC rows it implements.
5. **Decisions and rejected approaches** — link the D-n rows; say what was tried and dropped.
6. **Build, test, deploy, recover** — exact commands, from a clean machine.
7. **Known defects and traps** — see docs/next.md and knowledge/candidates/.
8. **Demonstrations** — scripted walkthroughs (and recordings, if any) linked to AC rows.
